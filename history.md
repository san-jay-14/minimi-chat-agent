## Phase 4: Answer contract and grounding
- Owner said "Yes, Phase 4".
- **Decision:** the grounding unit is a sentence or a table cell, not a whole answer or a whole table row. A citation vouches for the figures next to it. Reason: the model's totals ("20 seats x $14 = $280") are never in a source and would be flagged on every comparison. Instead the prompt tells the model to put derived figures in their own uncited sentence or table cell, and the check skips units with no citation.
- **Decision:** the check looks only at prices (`$`, `US$`, euro, pound, rupee, yen symbols, or a `USD/EUR/GBP/INR` suffix), percentages and version numbers (`v2.1`, `1.2.3`). Plain integers and dates are ignored, because checking them would flag almost every sentence. Numbers are compared by value after stripping commas and trailing zeros (`$1,500.00` equals `1500`). Weakness accepted per ARCHITECTURE.md: the number can match any number in the source (a `$20` claim passes if the text contains `20` anywhere).
- **Decision:** the text a citation is checked against is exactly what the model was shown: title plus `content` (live reads) or `snippet` (searches). With several citations in a unit, a figure may come from any of them.
- **Decision:** the **sources list is code, not model output**: `citedSources()` returns the cited results in order of first mention, and the loop returns them as `sources` (title, url, published, crawled) for the `sources` SSE event in Phase 5. The model is told not to write a list. Saves output tokens, and the dates cannot be mis-copied.
- **Decision:** the **"As of" line is appended by code** (`asOf` input, only when at least one search ran), so it can never be forgotten or wrong. The **Checked line stays model-written**, because only the model knows which items it called unchanged; the prompt requires it for any "unchanged as checked" item and bans "nothing changed". A code-generated backstop for a missing Checked line was considered and not built (see below).
- **Decision:** on failure there is no regeneration. Tokens have already streamed, so the notes (`Couldn't verify: $25 (cited R1)`, `Couldn't verify: [R9] is not a source from this turn`) go out as one last `token` event and are appended to the returned answer, together with the As-of line. Failures are logged with `console.warn("[grounding]")`.
- Wrote `src/agent/grounding.ts` (`checkGrounding`, `citedSources`), wired into `runAgent` (new input `asOf`; new result fields `sources`, `grounding`), added the contract to `src/agent/prompt.ts` (7 numbered rules: direct answer first, one line per item with the earlier answer and its date, exact verdict vocabulary, citation and derived-figure rule, no sources or As-of line from the model, Checked line, couldn't-verify wording, brevity).

## Phase 5: Server and UI
- Owner said "Yes, Phase 5".
- **Decision:** split the Hono app into `src/app.ts` (`createApp({memory, run, search})`) and a 7-line `src/server.ts` that only listens. Reason: tests can inject a fake agent and a fake search provider with `app.request()`. ARCHITECTURE.md layout updated (app.ts, search/provider.ts).

- **Decision:** keys are checked lazily. The server starts and serves the page with no keys (Phase 0 requirement). ### Step 5: citations and sources (done)
- Owner said "Yes, step 5".
- **Files:** `public/render.js` gained `renderInto()` and citation linking; new `public/sources.js` (`sourceList()`, moved out of app.js and extended); `app.js` calls `view.setSources()` when the `sources` event arrives; chip and sources-list CSS. No server change: the `sources` event already carries id, title, url, domain, published and read_live_at.
- **How chips work:** after markdown is rendered and sanitized, a tree walker finds text containing `[R#]` (also `[R1, R2]`, `[R1][R2]`) and replaces each marker with a small pill labelled with the source's domain, linking to the source in a new tab (`noopener noreferrer`), with a tooltip of "title · published date". Built only with DOM calls on the already-sanitized tree, so untrusted text can never become a link or element by itself. Markers inside code, code blocks or existing links are left alone.
- **Three states of a marker:** before the `sources` event arrives it is a muted placeholder with its id (so a streaming answer never shows a broken link); once the event arrives the placeholders become real chips; an id that is not among the sources stays as visible `[R9]` text (this is also how a grounding "Couldn't verify: [R9]..." line stays readable). A source with a non-web URL (for example `javascript:`) becomes a plain pill with no link.
- **Sources list:** under the answer, a "Sources" block: title as a link, then domain, then "published <date>" or "no published date", and "read live <time>" for pages read live. Dates are formatted from the ISO value in UTC so a date-only value does not shift a day. Only sources the answer cites are listed (that is what the server sends). **No favicons or other external images:** they would be requests to third-party hosts, which the brief forbids.
- **Real checks in the browser** (the page's real modules, 8 scenarios): chip text/href/target/rel/tooltip correct; `[R1][R2]` and `[R1, R2]` give separate chips; a chip inside a table cell; unknown id stays text; a `javascript:` source gives a span with no href; code and a link containing a marker untouched; hostile text (img onerror, script, attribute injection through a fake marker) created no elements and executed nothing; placeholders ("chip pending") became real links after `setSources`; a marker split across stream chunks (`[`, `R`, `1`, `]`) ended as one chip with no leftovers.
